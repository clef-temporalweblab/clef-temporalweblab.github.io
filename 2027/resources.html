Datasets and corpus

Task 1 questions

Question files with recency labels for training and development. Hidden labels will be retained for the official test set.

Task 2 archive records

A frozen, processed collection derived from selected End of Term captures, with stable record IDs and temporal metadata.

Retrieval indexes

A ready-to-use BM25 index is planned so that participants can begin with lexical retrieval without processing the full corpus themselves. Participants may also build dense or hybrid indexes over the same frozen records.

  • Official record identifiers must be preserved in every custom index.
  • Dense retrieval systems should index only the released corpus unless the final rules explicitly allow auxiliary evidence.
  • Index configuration and preprocessing details should be reported in the team paper.

Evaluation tools

Official scorers and submission validators will be released before the evaluation phase. Local validation should catch missing IDs, invalid labels, duplicate predictions, and malformed answer fields before upload.

Storage and hardware

The pilot corpus is expected to contain approximately 1–3 million processed records and require about 15–40 GB before participant-built indexes. Actual disk use will depend on the release format and indexing method.

  • Allow additional storage for decompression, BM25 segments, or dense embeddings.
  • Task 1 should run on substantially lighter hardware than full-corpus Task 2 systems.
  • CPU baselines will be documented where practical; GPU requirements will depend on the chosen language and embedding models.

Licensing, versions and citation

The planned corpus licence is CC0, while organizer-created annotations are planned for CC BY 4.0. Each release will include attribution guidance, citation text, version numbers, file sizes, and cryptographic checksums.

Participants should record the exact corpus, question, index, and scorer versions used for every submitted run.
