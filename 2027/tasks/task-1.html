Task 1 · Ordinal classification

Question Recency Requirement Estimation

Predict how soon the currently correct answer to a question is expected to become outdated or incorrect.

Overview

Information changes at different rates. Some answers may become outdated within hours, while others remain valid for years or are not expected to change. Task 1 asks systems to estimate a question's recency requirement: how soon its currently correct answer is expected to become outdated or incorrect, considering any accompanying context.

Systems assign one of twelve ordered recency classes, ranging from highly dynamic information to information that is not expected to change. Systems are not required to generate the factual answer itself.

Why does recency estimation matter?

Search and question-answering systems increasingly operate over information that changes over time. However, different questions require very different levels of freshness. A question about current weather may require recently retrieved evidence, while another question may be answerable using information that remains valid for years.

Estimating a question's recency requirement can help systems determine how fresh their evidence should be, whether new retrieval is necessary, and how aggressively previously retrieved or cached information should be refreshed. Rather than treating information as simply current or outdated, this task models freshness requirements across multiple temporal scales.

Campaign status: The task definition is established, while release links, final split sizes, and exact submission dates will be added when confirmed.

Task definition

Given a natural-language question and, where provided, its temporal context, the goal is to predict how soon a currently correct answer is expected to change for the first time and therefore become outdated or incorrect.

The prediction must be exactly one label from the twelve ordered recency classes defined below.

The task concerns the expected validity horizon of the answer. It does not ask systems to estimate the age of a document containing the answer, and it does not require systems to generate the answer itself.

Input and output

Input

A natural-language question, with accompanying temporal context where provided in the released dataset.

Output

Exactly one label from the twelve ordered recency classes.

When context is provided, the prediction should reflect the question under that specific context rather than its typical recency requirement in isolation.

Illustrative examples

Question Prediction Interpretation
What is the current temperature in Innsbruck? A-Few-Hours The currently correct answer may become outdated within a few hours.
What is the current monthly unemployment rate? A-Month The reported value is typically updated on approximately a monthly timescale.
Who currently holds a particular institutional office? A-Few-Years The answer may remain valid for several years before the office holder changes.
What is the chemical symbol for gold? Never The answer is not expected to change.

These examples are illustrative. The correct class for a dataset instance is determined by the question together with any context supplied for that instance.

Recency classes

The twelve classes represent progressively longer expected validity periods, from highly dynamic information to information that is not expected to change.

Order Class Interpretation
1 An-Hour Expected to change within an hour.
2 A-Few-Hours Expected to change within a few hours.
3 A-Day Expected to change within a day.
4 A-Few-Days Expected to change within a few days.
5 A-Week Expected to change within a week.
6 A-Few-Weeks Expected to change within a few weeks.
7 A-Month Expected to change within a month.
8 A-Few-Months Expected to change within a few months.
9 A-Year Expected to change within a year.
10 A-Few-Years Expected to change within a few years.
11 Many-Years Expected to change only after many years.
12 Never Not expected to change.

The scale uses finer distinctions for rapidly changing information and progressively broader intervals at longer temporal horizons.

Dataset and splits

The campaign dataset is derived from RecencyQA and contains questions spanning a broad range of expected answer-validity horizons, from rapidly changing information to stable facts.

Some questions may also be accompanied by temporal context that specifies the situation in which the question is being asked. Such context can affect the appropriate recency class.

Evaluation

Because the recency labels form an ordered scale, the evaluation considers both exact classification performance and the ordinal distance between predicted and gold classes.

Metric Purpose
Macro-F1 Primary metric; gives equal importance to every recency class.
Strict accuracy Counts only exact class predictions as correct.
Tolerant accuracy Counts predictions within one adjacent class of the gold label as correct.
Mean absolute ordinal distance Measures the average distance between the predicted and gold classes on the ordered recency scale.
Under-estimation rate Measures how often a system predicts a longer validity period than the gold label, potentially underestimating the need for fresh information.

Baselines

Planned starter systems include a majority-class baseline, supervised multiclass classification, ordinal classification, and zero- and few-shot language-model prompting.

Baseline implementations and evaluation scripts will be released with the campaign resources.

Submission and participation

Teams will submit one valid recency label for every test question through TIRA. The current plan permits up to three runs per task, with one primary run identified for official reporting.

  • Teams may enter Task 1 without participating in Task 2.
  • Each run must use the released question identifiers and exact label spelling.
  • Systems are required to predict a recency class; generating the factual answer is not part of Task 1.
  • System descriptions should report training data, model, prompting or optimization method, and external resources.

Task 1 FAQ

Must systems answer the question?

No. The required output is the recency class representing how soon the currently correct answer is expected to become outdated or incorrect.

How should systems use the provided context?

When context is provided, systems should estimate the recency requirement of the question under that specific context. The same question may have different recency requirements in different temporal situations.

Is a neighbouring class accepted?

Macro-F1 and strict accuracy require the exact class. Tolerant accuracy additionally reports whether the prediction falls within one adjacent class of the gold label.

Why are the classes ordered?

The labels represent progressively longer expected answer-validity periods. Predicting a neighbouring class therefore represents a smaller temporal error than predicting a class several positions away.

Can external models or data be used?

Permitted external resources will be defined in the final participation rules and must be documented in system descriptions.
